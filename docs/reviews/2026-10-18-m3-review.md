## P1 · Reconcile legacy category names before enforcing uniqueness

`src-tauri/src/db/migrations/v5_category_nocase.sql` creates a unique index on `categories(name COLLATE NOCASE)`. V4's existing case-sensitive UNIQUE constraint permits `Groceries` and `groceries`. The new index rejects this data. Database initialization propagates that migration error and startup exits.

The new populated-upgrade test seeds only a single category, so 38 passing tests do not cover the failing legacy case.

### Reproduction using actual migration files

Run from the repository root. This uses an in-memory database and touches no application records.

```python
from pathlib import Path
import sqlite3

root = Path('src-tauri/src/db/migrations')
conn = sqlite3.connect(':memory:')
for name in ['v1_init.sql', 'v2_regional_foundation.sql',
             'v3_protect_currency_exponent.sql', 'v4_catalog.sql']:
    conn.executescript((root / name).read_text())
for identity, name in [('legacy-a', 'Groceries'), ('legacy-b', 'groceries')]:
    conn.execute('INSERT INTO categories '
                 '(id,name,created_at,updated_at) VALUES (?,?,0,0)',
                 (identity, name))
conn.commit()
conn.executescript((root / 'v5_category_nocase.sql').read_text())
# Current result: sqlite3.IntegrityError: UNIQUE constraint failed: categories.name
```

### Required correction

- Choose a deterministic canonical category per collision group.
- Preserve products by repointing their category references transactionally.
- Preserve or explicitly record metadata from merged legacy categories.
- Enforce the unique index only after reconciliation succeeds.
- Respect checksum-tracked migration history; do not blindly edit an already-applied migration. Assess both V4 upgrade and existing V5 installations.
- Test clean install, collision-free upgrade, collision upgrade with products, rollback on injected failure, repeat startup and foreign-key integrity.
- Do not delete the database, disable checksums or discard product assignments to make startup pass.
